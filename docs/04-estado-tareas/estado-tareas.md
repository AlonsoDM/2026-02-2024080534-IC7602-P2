# Estado de las tareas

Este documento divide el proyecto en tareas concretas. Cada tarea corresponde a un Pull Request. Una tarea no se considera finalizada solamente porque el código ya exista en una rama: debe cumplir su criterio de finalización y quedar integrada en `main`.

**Estados:** Pendiente / En progreso / Bloqueada / Finalizada.

## Reglas para actualizar este documento

- Una tarea pasa a **En progreso** cuando ya existe una rama o un PR trabajando específicamente en ella.
- Una tarea pasa a **Finalizada** cuando se integró, cumple su criterio de finalización y tiene la evidencia correspondiente.
- Si una tarea se marca como **Bloqueada**, en la evidencia se indica qué falta y cuál tarea o decisión la bloquea.
- El avance y la evidencia se actualizan en el mismo PR que cambia el estado de la tarea.
- Cada PR indica el ID de su tarea, por ejemplo `T-12`, e incluye sus pruebas y su documentación.
- Si se cambia un contrato de la sección 5 del README o una decisión de arquitectura, el mismo PR actualiza el README y `docs/03-arquitectura/`.
- No se mezclan varias tareas en un mismo PR.

La columna **Depende de** indica qué debe estar listo para cerrar una tarea. No impide empezarla antes con funciones vacías o respuestas fijas cuando el contrato ya está acordado.
